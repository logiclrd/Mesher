## M30 test review: avoid premature mixed-worker acceptance

The interim M30 Windows rerun exposed a separate false-positive
in the M34 integration test. `rejectedUnions` includes certain
failed `physicalExact` stamps as well as independently queued
exact commands. `waitForUnion(worker,3)` could therefore return
from a counter value reached by the physical refusal BEFORE
the newly enqueued stale explicit Merge ran. The old test
sometimes passed on Linux by accident and intermittently
failed on Windows. The corrected test records
`completedUnions+rejectedUnions` immediately after the
physical refusal, queues the stale-root Merge and waits for
ONE ADDITIONAL explicit union outcome. It then requires
the new rejection count, no new completed union, the exact
`stale` reason, unchanged history and publication count,
and no renderer snapshot. Only then does later physical
FIFO input begin. All 23 suites pass with this genuine
completion fence on GCC, Clang and MSVC.
