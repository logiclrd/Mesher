# Mesher documentation guide

historical development/acceptance record. The chronological files
are retained because their positive and refusal cases contain
technical details that should not be rewritten as broad promises.

## Process

Milestones are flat and independently completable. If a task is
larger than one pass, add the **full planned remainder** as flat
peers to `todo.md` before continuing; do not repeatedly nest or
leave a partly completed item ambiguously checked. Each milestone
requires actual positive and refusal coverage and exact PR-head
plus independent merged-main CI on GCC/Clang/MSVC. Retain human
GPU observations and CPU proofs as separate evidence.
